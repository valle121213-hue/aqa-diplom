
# Отчёт по тестированию сервиса покупки тура

## 1. Краткое описание

В рамках тестирования проведена проверка веб-сервиса покупки тура `aqa-shop.jar`.

Тестирование проводилось для двух сценариев:
* форма «Купить»;
* форма «Купить в кредит».

Проверялись:
* корректность обработки валидных и невалидных данных;
* валидация полей формы;
* обработка запросов с APPROVED- и DECLINED-картой;
* отображение сообщений полей формы пользователю;
* корректность сохранения результатов операций в базе данных;
* соответствие данных в пользовательском интерфейсе и базе данных.

По результатам тестирования выполнено 28 тест-кейсов.

## 2. Окружение

* **Операционная система:** macOS Ventura 13
* **IDE:** IntelliJ IDEA
* **Java:** 11.0.31

## 6. Выявленные дефекты

В ходе тестирования выявлено **5 уникальных дефектов**.

### DEFECT-01 — DECLINED-платёж отображается как успешный

**Форма:** «Купить»

При использовании DECLINED-карты интерфейс отображает сообщение об успешной операции:

> «Успешно — Операция одобрена Банком!»

При этом в базе данных платёж сохраняется со статусом `DECLINED`.

Дополнительно создаётся запись в `order_entity`.

---

### DEFECT-02 — При пустом CVC появляется дополнительная ошибка у поля «Владелец»

**Формы:** «Купить», «Купить в кредит»

При пустом поле CVC отображается ошибка «Неверный формат» у CVC/CVV. Дополнительно отображается ошибка «Поле обязательно для заполнения» у поля «Владелец», хотя поле заполнено.

---

### DEFECT-03 — Поля формы остаются подсвеченными после корректного заполнения

**Формы:** «Купить», «Купить в кредит»

После отправки пустой формы и последующего заполнения всех полей валидными данными поля «Номер карты», «Владелец» и «CVC/CVV» остаются подсвеченными как ошибочные.

---

### DEFECT-04 — При успешной покупке в кредит заказ не связывается с кредитной заявкой

**Форма:** «Купить в кредит»

При успешной операции кредитная заявка создаётся со статусом `APPROVED`, однако в `order_entity` поле `credit_id` имеет значение `NULL`.

Дополнительно в поле `payment_id` записывается значение `bank_id` кредитной заявки вместо идентификатора кредитной заявки.

---

### DEFECT-05 — DECLINED-кредит отображается как успешный

**Форма:** «Купить в кредит»

При использовании DECLINED-карты интерфейс отображает сообщение об успешной операции.

При этом в базе данных кредитная заявка имеет статус `DECLINED`, а в `order_entity` создаётся заказ с `credit_id = NULL`.

## 7. Общие рекомендации

1. Исправить обработку DECLINED-операций, чтобы сообщение в интерфейсе соответствовало фактическому статусу операции в базе данных.
2. Проверить логику валидации полей формы, в частности зависимость ошибки поля «Владелец» от состояния поля CVC.
3. Исправить очистку состояния валидации после повторного корректного заполнения формы.
4. Проверить сохранение связей между `order_entity` и `credit_request_entity` при успешной покупке в кредит.
5. Проверить логику создания заказа при отклонённой кредитной операции.
6. После исправления дефектов выполнить повторное тестирование затронутых сценариев.
